## 创建职位 {#create}

**新建职位**会在对话框中打开表单，分为*基本信息*（标题、描述、URL、语言、参考编号、类别）、*分类*（类型、工作方式、级别、标签）、*工作量和薪资*、*日期*、*地点*和*订阅源*。URL 是申请人应前往的地方——您的招聘页面或申请人跟踪系统。

标签和地点通过搜索来选择。如果您想要的标签尚不存在，请输入其名称并选择 **创建标签“…”**：它会在保存职位时创建；如果保存失败，则完全不会创建。

新职位会保存为**草稿**。**保存草稿**会保持草稿状态；**保存并激活**还会尝试将其激活，如果缺少信息，则保存为草稿并准确列出缺少的内容。

**职位只在其所属的订阅源中发布。** 在*订阅源*下勾选所属的订阅源；新职位一开始位于 *All jobs* 订阅源中。通过 API 创建的职位也会放在那里。

## 状态 {#states}

| 状态 | 含义 |
|---|---|
| **草稿** | 准备中。信息不完整也没关系。从不发布。 |
| **已激活** | 准备发布。 |
| **已停用** | 已撤回、已招满或已归档。保留作记录，从不发布。 |

草稿可以激活，如果不再需要也可以删除；已激活的职位可以退回草稿或停用；已停用的职位可以重新激活。职位首次激活的日期会保留为其发布日期，以后编辑时不会改变。

## 发布就绪情况 {#readiness}

只有满足所有发布要求的职位才能激活。职位页面以清单形式显示这些要求，即**发布就绪情况**，每个未满足的要求都链接到可以修正它的字段：

- 状态为已激活，且已设置发布日期；
- 标题、URL、语言和类型均已填写；
- 至少有一个地点；
- 如果填写了薪资，也要填写其货币和周期；
- 处于其日期范围之内。

## 日期范围 {#date-window}

当职位的**申请截止日期**或**结束日期**已过时，职位会自动离开其订阅源——无需任何人编辑它。它仍保持激活状态，如果您调整日期，它会自动回到订阅源中。**开始日期**从不会移除职位：一个三个月后才开始的职位是很正常的招聘信息。

## 职位的显示状态 {#shown-as}

职位列表和职位页面显示职位当前呈现的状态：

| 显示为 | 原因 |
|---|---|
| **已发布** | 已激活、信息完整且处于日期范围内：它在其订阅源中。 |
| **已过期** | 已激活，但其申请截止日期或结束日期已过。 |
| **不完整** | 已激活，但某项要求不再满足，例如其最后一个地点已被移除。 |
| **草稿** | 草稿。 |
| **已停用** | 已停用。 |

只有**已发布**的职位才会出现在订阅源中。职位页面还会列出它所属的订阅源，并提供一个字段用于将其加入其他订阅源；如果一个已可发布的职位不在任何订阅源中，页面会发出警告。页面还会显示其**状态历史**：谁在什么时候将其状态从什么改为什么。

## 职位链接和点击 {#clicks}

在已发布的订阅源中，职位链接指向本应用，本应用会统计点击并将访问者转到您的 URL。点击只按天和国家/地区统计——不存储任何地址或浏览器信息。仪表板会显示这些点击。一旦职位不再发布，其链接会告诉访问者该职位已不存在，而不再转发。

## 删除职位 {#delete}

任何状态下都可以删除。确认信息会列出该职位将从哪些订阅源中消失。
